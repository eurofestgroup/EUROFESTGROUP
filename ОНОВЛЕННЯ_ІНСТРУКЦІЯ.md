# Актуальне оновлення: усі 8 покращень вигляду та зручності

1. Плавні короткі переходи між сторінками. У сучасних браузерах працює анімація переходу; в інших — легке затемнення. Посилання, нові вкладки, переходи до розділів і кнопка «Назад» зберігають звичну поведінку.
2. Фото розгортається зі своєї мініатюри у великий перегляд і повертається до відповідної картки. Поки оригінал завантажується, видно мініатюру. Стрілки, свайпи, Escape, кнопка закриття та відкриття оригіналу працюють як раніше.
3. Оновлена типографіка: локальні стиснені шрифти з українськими й англійськими символами, виразні заголовки та акуратні переноси. Шрифти входять до папки `assets/fonts`; зовнішній сервіс шрифтів не потрібен.
4. На телефоні — нижня скляна панель «Головна / Події / Новини / Фото». Врахована нижня безпечна зона екрана; в кінці сторінки залишено місце, щоб панель не закривала останні кнопки. У перегляді фото або деталей події вона ховається.
5. Спробна журнальна розкладка галереї: великі акцентні кадри між меншими фотографіями. Порядок фотографій і поступове завантаження збережені. Цю зміну можна вимкнути окремо.
6. Спробний відеофон на головній. Це 12-секундна петля з наявного зображення вантажівок і плавного руху камери. WebM — приблизно 431 КБ, MP4 — приблизно 671 КБ; браузер завантажує один формат. Відео починає завантажуватися через 8 секунд лише на ПК, коли перший екран видно. На телефонах і планшетах шириною до 1100 px, при вимкнених ефектах, зменшеному русі, економії трафіку чи повільному з’єднанні залишається звичне фото. Відео без звуку; на іншому розділі або у фоновій вкладці воно зупиняється. Цю зміну можна вимкнути окремо.
7. Скляні кнопки м’яко реагують на натискання й короткий світловий відблиск. Працює мишею, дотиком і клавіатурою.
8. Власна сторінка `404.html` у стилі EUROFEST: фон, номер 404, дві мови й кнопки повернення на головну або до подій. На GitHub Pages вона також працює для помилкових адрес із кількома вкладеними частинами.

Звичне скло та чорно-червона палітра збережені. На головній як і раніше максимум **6 подій** і **6 новин**. Повні списки, архів, DLC, інформація з Discord/TruckersMP, оригінали фотографій та кеш 100 фото залишаються на своїх місцях. Кнопка вимкнення ефектів і системна опція зменшеного руху враховуються новими анімаціями.

## Що і куди закинути — лише GitHub

1. Завантаж і розпакуй `EUROFEST_GROUP_website.zip`.
2. Відкрий папку `EUROFEST_GROUP/github-pages`.
3. Відкрий свій репозиторій сайту на GitHub → **Add file → Upload files**.
4. Завантаж **увесь вміст** `github-pages` у корінь репозиторію, з якого публікується GitHub Pages: `index.html`, `events.html`, `news.html`, `photos.html`, `archive.html`, новий `404.html`, `sw.js`, папку `assets` і нову папку `media`. Завантажуй вміст, а не зовнішню папку `github-pages`. Усередині `assets` обов’язково має залишитися папка `fonts`. Якщо публікуєш із папки `docs`, завантаж цей вміст саме в `docs`.
5. Натисни **Commit changes** й дочекайся завершення GitHub Pages deployment.
6. Відкрий сайт із **Ctrl+F5**. Для перевірки відео відкрий головну на ПК, залиш її на першому екрані приблизно на 8 секунд і переконайся, що ефекти ввімкнено. На телефоні має бути статичний фон і нижня навігація. Перевір обидві мови та галерею.

**Для цього оновлення на хостинг нічого закидати й перезапускати не потрібно.** Якщо попереднє оновлення вже працює, залиш БД, конфіг хостингу, API і лаунчер як є. Папка `hosting` в архіві збережена для повного комплекту.

## Якщо напишеш «5 відміна» або «6 відміна»

Відкрий на GitHub файл `assets/config.js`, зміни лише потрібний перемикач і збережи commit:

| Що повернути | Зміна |
|---|---|
| Попередня рівна сітка фотографій — «5 відміна» | `galleryMagazine: false` |
| Попередній статичний фон — «6 відміна» | `heroVideo: false` |

Перемикачі незалежні. Можна вимкнути лише №5, лише №6 або обидва. Решта шести покращень продовжить працювати. Щоб знову ввімкнути, поверни `true`. Адресу `apiUrl` під час цього не змінюй. Після deployment онови сторінку.

Для звичайного сайту GitHub Pages із адресою `https://ім’я.github.io/назва-репозиторію/` сторінка 404 визначає папку автоматично. Якщо колись зробиш сайт у самому корені `https://ім’я.github.io/`, у `404.html` встанови `const manualBase = '/';`. Для іншого хостингу з нестандартною вкладеною папкою вкажи її у цій самій змінній.

# Попереднє оновлення: невідомі DLC уточнюються через TruckersMP

Для `EFG-0013` у БД збережено `(не відома інформація)`. Перевірена відповідь TruckersMP для його події `35272` містить `dlcs: []` — потрібних DLC немає.

Тепер при відкритті деталей конвою:

- Наявні DLC з БД показуються одразу та залишаються посиланнями на купівлю.
- Якщо поле порожнє або містить старе повідомлення про невідому інформацію, API уточнює DLC за посиланням на подію TruckersMP із цієї БД.
- Підтверджений порожній список від TruckersMP показується як «DLC не потрібні» / «No DLC required».
- Потрібні DLC із TruckersMP стають посиланнями на відповідні сторінки Steam.
- Якщо подію або дані не вдалося отримати, показується «DLC уточнюються» / «DLCs to be confirmed». Помилка запиту не означає, що DLC не потрібні.

БД читається без запису. Перевірка запускається лише для відкритої події з відсутніми DLC; список, фото, маршрут і слот не чекають на цей запит. Результати кешуються на 15 хвилин, помилки — на 1 хвилину. На сервері зберігається максимум 100 невеликих записів у пам’яті, файли та фотографії не створюються; одночасно допускаються максимум 2 запити до TruckersMP. Наявні дані, які ти відредагував у БД, мають пріоритет.

Доопрацьовано: стриманіше скло, нейтральніші темні поверхні, узгоджені рамки й відступи, читабельніші другорядні підписи, фірмова смуга без обрізання на телефоні, підсвічування активного розділу, зручніші області натискання, переходи для вікон, плавна поява фотографій після завантаження та акуратні заглушки без значка зламаного зображення. На сенсорному екрані картки не залишаються в піднятому стані наведення. Архів має заголовок сторінки та швидке посилання до календаря; календар — до архіву.

Всі дані продовжують надходити з попередніх API. Кешування перших 100 фото після 6 секунд, підвантаження шести наперед, UA/EN, деталі подій та оригінали фотографій збережені. Нових серверних залежностей, збереження фото на хостингу або прив’язки фотографій до конвоїв не додано.

# EUROFEST: кеш фотографій на пристрої відвідувача

## Що завантажити

1. Розпакуй EUROFEST_GROUP_website.zip.
2. На GitHub заміни сайт вмістом EUROFEST_GROUP/github-pages/: index.html, photos.html, archive.html, sw.js та папку assets. Всі HTML-файли й sw.js лежать у корені сайту поруч із assets, без зовнішньої папки github-pages.
3. На хостингу натисни STOP. З папки hosting заміни **site_events_api.py** та **site_community.py** поруч із eurofest_convoys.db.
4. БД, site_settings.json, токен, лаунчер та існуючий requirements.txt не замінюй. Pillow більше не потрібна для сайту; нових залежностей немає.
5. Якщо вже встановив попередню версію із серверними прев’ю, при зупиненому API можеш видалити лише папку **site_media_cache** та допоміжний файл **site_media.py**. У цій версії вони не використовуються. Не видаляй БД або інші файли ботів.
6. Натисни START із тією ж командою запуску лаунчера. Допоміжний site_community.py окремо не запускається.
7. Дочекайся GitHub Pages deployment. Відкрий сайт, за потреби Ctrl+F5. Залиш головну відкритою — через 6 секунд почнеться фонове кешування фотографій.

## Як це працює

- На головній або сторінці архіву через 6 секунд запускається підготовка перших 100 фотографій, якщо в галереї їх стільки є. Це запуск процесу, а не гарантія завантаження всіх фото за 6 секунд. Фонові завдання можуть завершуватися поступово протягом хвилин залежно від інтернету і джерела.
- Під час переходу між сторінками кеш зберігається. Черга відновлюється: вже збережені файли повторно не скачуються. Завдання, які не встигли завершитися до переходу/закриття вкладки, можуть початися заново.
- Кеш фотографій знаходиться на пристрої відвідувача, у Cache Storage його браузера. Стиснення до прев’ю максимум 800 px виконується на цьому пристрої, переважно в окремому Worker. Вигляд сітки, кольори та розташування блоків не змінюються. Оригінали залишаються для повноекранного перегляду. Анімації не замінюються статичними прев’ю.
- Працюють максимум два фонові завантаження одночасно. Видимі в галереї фото отримують пріоритет; решта сотні готується у фоні. При прихованій вкладці нові завдання призупиняються, вже активні можуть завершитися.
- Галерея показує по 24 картки. Фотографії, що наближаються до видимої області, кешуються за потреби; після показаної групи додатково готуються наступні 6. Під час повноекранного перегляду наступний оригінал підвантажується через звичайний кеш браузера. Всі 500 оригіналів заздалегідь не скачуються.
- Для повторного входу браузер використовує збережені прев’ю. Локальний кеш обмежений приблизно 100 MB та 500 записами; найстаріші прибираються при перевищенні. Браузер може виділити менше місця або сам очистити сховище. За нестачі місця всі 100 фотографій не гарантовано збережуться; сайт продовжить працювати.
- Оформлення, скрипти та сторінки також кешуються через sw.js після затримки. Service Worker має область лише цього сайту. Сторінки та config.js перевіряються через мережу; інформація про події, новини, команду і галерею продовжує оновлюватися з API. Кеш не підтверджує доступність динамічних даних без інтернету.
- Фотографії, видалені з актуального списку Discord, видаляються з керованого кешу після отримання нового успішного списку. Збій API не очищує весь кеш.
- Якщо приватний режим або налаштування браузера блокують сховище, галерея працює без гарантованого постійного кешу.

## Ресурси хостингу та перше завантаження

Сервер не генерує прев’ю і не зберігає фотографії на диску. Основне джерело — Discord напряму. Якщо Discord блокує CORS для читання з браузера, маршрут /api/photo-source/ID передає тільки відому фотографію з галереї, порціями по 64 KB, максимум два потоки та 20 MB на файл. Він не приймає довільні зовнішні URL. При цьому витрачається трафік хостингу, але файл не завантажується цілком в оперативну пам’ять і не записується на диск.

Перший візит із прогрівом 100 фото витрачає інтернет-трафік відвідувача. Якщо прев’ю Discord недоступні, для створення локального малого прев’ю спершу потрібно скачати оригінал. Усі наступні перегляди того самого прев’ю використовують кеш за його наявності. Помилки фото мають запасний перехід до оригіналу.

## Що залишилось

Архів подій, UA/EN, мобільна версія, ефекти, новини, команда та партнери залишились. Фото знаходяться в загальній галереї без прив’язки до конвоїв. Поточна версія показує на головній по 6 подій і новин, а повні списки — на окремих сторінках, як описано на початку цієї інструкції. API читає існуючу БД, не змінює її. Минулі події потрапляють в архів після виїзду + 3 години або після кінця дня без часу виїзду; CANCELLED і DRAFT не показуються. Видалені ботом записи не зберігаються окремо.
